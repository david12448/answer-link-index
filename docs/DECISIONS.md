# Architecture Decisions

프로젝트 운영 중 결정한 원칙과 이유를 기록합니다.

## ADR-001 — 답지 파일을 직접 재호스팅하지 않는다
- 저장소에는 PDF/HWP 파일 자체가 아니라 공식 출판사 공개 위치를 인덱싱한다.
- 저작권, 최신판 교체, 저장소 용량 문제를 줄이기 위한 결정이다.

## ADR-002 — 교재 ID와 URL을 분리한다
- 교재는 book_id, 자료는 resource_id로 식별한다.
- 출판사 URL이 바뀌어도 같은 교재 레코드는 유지한다.

## ADR-003 — URL을 3단계로 관리한다
1. official_page: 공식 교재 안내 페이지
2. resource_page: 정답·정오표 등 공식 자료 페이지
3. direct_url: 공식 직접 다운로드 주소

## ADR-004 — 공식 교재 페이지도 주기적으로 검사한다
- direct_url뿐 아니라 official_page와 resource_page도 주 2회 확인한다.
- 기본 일정은 매주 월요일·목요일 오전 9:15 KST이다.

## ADR-005 — 자동 발견과 자동 수정은 분리한다
- 자동화는 상태 변화, redirect 최종 주소, 404/403 등을 발견하고 보고한다.
- catalog URL 자체의 자동 교체는 하지 않는다.
- 실제 교재가 맞는지 확인한 후 별도 PR에서 반영한다.

## ADR-006 — 출판사별 수집기는 독립적으로 작성한다
- 사이트 구조가 서로 다르므로 수집기는 출판사별로 분리한다.
- 최종 catalog 데이터 형식만 공통 정규화 단계에서 통일한다.

## ADR-007 — 로그인/교사용 제한은 우회하지 않는다
- 로그인 필요 또는 교사 인증 자료는 access 상태로 표시하고 공식 페이지까지만 안내한다.


## ADR-008 — 로그인 계정은 공개 저장소에 저장하지 않는다
- 출판사 개인 계정의 아이디·비밀번호·세션 쿠키·토큰은 catalog, 코드, Actions 로그에 기록하지 않는다.
- 로그인 필요 자료는 `access: login_required`로 표시하고 공식 로그인/자료 페이지로 연결한다.
- 로그인 후에만 생성되는 일회성·세션성 다운로드 URL은 공개 direct_url로 저장하지 않는다.
- 향후 인증이 필요한 자동 수집이 꼭 필요하면 공개 인덱스 저장소와 분리된 비공개 실행 환경 또는 로컬 수집기를 사용한다.
