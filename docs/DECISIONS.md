# Architecture Decisions

프로젝트 운영 중 결정한 원칙과 이유를 기록합니다.

## ADR-001 — 답지 파일을 직접 재호스팅하지 않는다
- 저장소에는 PDF/HWP 파일 자체가 아니라 공식 출판사 공개 위치를 인덱싱한다.
- 저작권, 최신판 교체, 저장소 용량 문제를 줄이기 위한 결정이다.

## ADR-002 — 교재 ID와 URL을 분리한다
- 교재는 book_id, 자료는 resource_id로 식별한다.
- 출판사 URL이 바뀌어도 같은 교재 레코드는 유지한다.

## ADR-003 — URL을 3단계로 관리한다
1. official_page: 공식 교재 안내 페이지
2. resource_page: 정답·정오표 등 공식 자료 페이지
3. direct_url: 공식 직접 다운로드 주소

## ADR-004 — 공식 교재 페이지도 주기적으로 검사한다
- direct_url뿐 아니라 official_page와 resource_page도 주 2회 확인한다.
- 기본 일정은 매주 월요일·목요일 오전 9:15 KST이다.

## ADR-005 — 자동 발견과 자동 수정은 분리한다
- 자동화는 상태 변화, redirect 최종 주소, 404/403 등을 발견하고 보고한다.
- catalog URL 자체의 자동 교체는 하지 않는다.
- 실제 교재가 맞는지 확인한 후 별도 PR에서 반영한다.

## ADR-006 — 출판사별 수집기는 독립적으로 작성한다
- 사이트 구조가 서로 다르므로 수집기는 출판사별로 분리한다.
- 최종 catalog 데이터 형식만 공통 정규화 단계에서 통일한다.

## ADR-007 — 로그인/교사용 제한은 우회하지 않는다
- 로그인 필요 또는 교사 인증 자료는 access 상태로 표시하고 공식 페이지까지만 안내한다.


## ADR-008 — 로그인 계정은 공개 저장소에 저장하지 않는다
- 출판사 개인 계정의 아이디·비밀번호·세션 쿠키·토큰은 catalog, 코드, Actions 로그에 기록하지 않는다.
- 로그인 필요 자료는 `access: login_required`로 표시하고 공식 로그인/자료 페이지로 연결한다.
- 로그인 후에만 생성되는 일회성·세션성 다운로드 URL은 공개 direct_url로 저장하지 않는다.
- 향후 인증이 필요한 자동 수집이 꼭 필요하면 공개 인덱스 저장소와 분리된 비공개 실행 환경 또는 로컬 수집기를 사용한다.


## ADR-009 — 공개 인덱스와 인증 수집기를 분리한다
- 공개 answer-link-index에는 정제된 교재 정보와 공개 가능한 공식 링크만 둔다.
- 로그인이 필요한 출판사의 수집 코드는 별도 private repository에서 실행한다.
- 출판사 계정 정보는 private repository 파일에도 저장하지 않고 GitHub Actions Secrets 또는 로컬 환경변수로만 주입한다.
- private collector에서 발견한 링크는 세션/토큰 의존 여부와 공개 접근 가능성을 검사한 뒤 공개 저장소로 보낼 후보 데이터만 만든다.
- 공개 저장소 반영은 자동 덮어쓰기보다 PR 검토 방식으로 진행한다.

## ADR-010 — 전체 검색과 티스토리 embed를 같은 데이터로 제공한다
- GitHub Pages 기본 화면은 전체 교재 검색기로 유지한다.
- 티스토리에서는 같은 페이지에 `embed=1`과 `publisher`, `subject`, `grade`, `book` URL 파라미터를 전달해 포스팅 범위를 고정한다.
- URL에서 이미 고정한 조건은 선택창에서 숨겨 사용자가 같은 조건을 반복해서 선택하지 않게 한다.
- 특정 `book`이 고정된 embed는 다른 교재 탐색 UI를 숨기고 해당 교재의 자료 버튼에 집중한다.

## ADR-011 — 대량 교재의 기본 보기는 compact 목록형으로 한다
- 교재가 수백~수천 권으로 늘어날 것을 전제로 기본 결과 화면은 1열 compact 목록형으로 한다.
- 표지 중심 탐색을 원하는 사용자를 위해 별도 표지형 보기 전환을 제공한다.
- 최초 20권만 렌더링하고 더보기 방식으로 추가 표시한다.
- 한 권을 선택했을 때만 상세형 레이아웃으로 확장한다.

## ADR-012 — 표지는 공식 출판사 URL을 참조하고 재호스팅하지 않는다
- `cover_image_url`은 공식 출판사/CDN 이미지 주소를 저장한다.
- 표지 로딩 실패 시 placeholder를 표시한다.
- 표지 URL도 주 2회 링크 검사 대상에 포함한다.
- 티스토리 글 연결이 필요할 경우 선택적으로 `post_url`을 저장하되, 교재 식별자나 공식 URL을 대신하지 않는다.

## ADR-013 — 출판사별 수집 방식은 달라도 사용자 UI는 하나로 정규화한다
- 출판사마다 교재 분류, 검색 파라미터, 로그인 여부, 자료실 구조가 달라도 그 차이는 collector/adapter 내부에서 처리한다.
- 사용자 화면은 출판사 구조를 그대로 노출하지 않고 **출판사 → 과목 → 학년 → 교재**와 교재명 검색을 공통 진입점으로 유지한다.
- 브랜드/시리즈는 데이터와 검색용으로 보존하되 사용자가 꼭 거쳐야 하는 필수 단계로 만들지 않는다.
- 출판사 고유 ID가 있으면 `publisher_book_id`로 보존하고, 최종 UI는 공통 catalog 계약만 소비한다.

## ADR-014 — 티스토리 개별 교재 포스팅을 1급 사용 시나리오로 취급한다
- 이 프로젝트의 배포 핵심은 GitHub Pages 전체 검색과 **티스토리의 교재별 개별 포스팅**을 동시에 지원하는 것이다.
- 모든 교재는 안정적인 `book_id`를 가지며 `?book={book_id}&embed=1` 형태로 한 권만 표시할 수 있어야 한다.
- 특정 교재 embed에서는 다른 교재 탐색 UI보다 정답/정오표/MP3/부가자료/인강 등 현재 교재 자료 접근을 우선한다.
- 티스토리 글 수백 개가 생겨도 링크 갱신은 GitHub catalog 한 곳에서 처리할 수 있어야 한다.
- `post_url`은 관련 티스토리 글 연결용 보조 필드이며 공식 출판사 URL과 분리한다.
## ADR-015 — 목록 화면에서는 외부 자료 URL을 직접 노출하지 않고 내부 교재 상세로 진입한다
- 교재 목록/표지 화면의 교재명과 표지는 `?book={book_id}` 내부 상세 페이지로 이동한다.
- 정답·정오표·MP3 등의 자료 뱃지도 목록에서는 외부 출판사 URL로 직접 이동하지 않고 내부 교재 상세로 이동한다.
- 자료 뱃지는 사용자가 마우스를 올렸을 때 외부 다운로드 주소가 노출되지 않도록 `javascript:void(0)` 진입 링크 + 클릭 이벤트 방식으로 처리한다.
- 실제 출판사 자료 URL은 내부 교재 상세 화면에서만 노출하고, `direct_url → resource_page → official_page` 우선순위를 따른다.
- 출판사 공식 교재 페이지는 상세 화면의 보조 링크로 유지한다.

## ADR-016 — EBS 자료는 직접 파일 우선, 상세 페이지 fallback을 보장한다
- EBS 정답지는 검증된 PDF `direct_url`을 얻으면 이를 최우선으로 사용한다.
- 직접 파일 URL을 안정적으로 얻지 못하면 `detailBkAnsInfo.ebs?bookId=...&no=...` 같은 교재별 정답지 상세 페이지를 `resource_page`로 사용한다.
- 정오표처럼 검색 화면을 거쳐야 하는 자료는 collector가 검색/상세 요청을 대신 수행해 존재 여부와 교재별 결과를 catalog에 반영하는 방향으로 구현한다.
- 자동 판별이 불확실한 동안에는 EBS 공식 검색/자료 페이지를 안전한 fallback으로 둔다.

## ADR-017 — EBS 정오표는 direct → 검색어 자동입력 → 공통 페이지 순으로 fallback한다
- 정오표 파일이 실제로 존재하면 `bkErrChrgMngFLdown.ebs?bookId=...` 공식 다운로드 주소를 `direct_url`로 사용한다.
- 정오표가 아직 없으면 `bookNm` 쿼리로 교재명이 미리 입력되는 EBS 정오표 검색 페이지를 `resource_page`로 사용한다.
- 검색어 자동입력 방식이 향후 EBS 변경으로 동작하지 않을 때만 공통 정오표 페이지를 최종 fallback으로 사용한다.
- 정오표는 주 2회 자동 점검하고, 새 정오표가 확인되어 catalog가 변한 경우에만 PR을 만든다.

## ADR-018 — EBS 초등·중학·고등은 사용자에게 하나의 출판사로 보인다
- EBS 초등(`primary.ebs.co.kr`), 중학(`mid.ebs.co.kr`), 고등(`ebsi.co.kr`)은 내부 수집기는 분리하되 UI의 출판사는 모두 `EBS`로 통합한다.
- 학교급 차이는 `school_level`, 내부 서비스 차이는 `publisher_site`로 구분한다.
- 고등은 `LB...`, 초등/중학은 `TB...` 계열의 출판사 교재 ID를 `publisher_book_id`로 보존한다.
- 사용자는 사이트별 구조를 알 필요 없이 출판사 → 과목 → 학년 → 교재 순서로 찾는다.
- 티스토리 개별 교재 포스팅도 학교급과 무관하게 같은 `?book={book_id}&embed=1` 계약을 사용한다.

## ADR-019 — 수집 규모 증가 시 사용자 UI를 함께 개선한다
- 기본 경로 **출판사 → 과목 → 학년 → 교재**와 교재명 직접 검색을 유지한다.
- 학교급이 혼재할 때만 **전체/초등/중등/고등** 빠른 선택을 제공하고 필수 단계로 강제하지 않는다.
- 학년은 초등 → 중등 → 고등 순으로 정렬하며, 큰 교재 드롭다운은 80권까지만 표시한다.
- 티스토리 목록 embed에서도 검색이 가능해야 하며, 개별 `?book={book_id}&embed=1`에는 검색·필터를 노출하지 않는다.
- 교재가 100·500·1,000권에 도달하거나 새로운 출판사가 추가될 때마다 모바일 화면을 포함한 UI 사용성 점검을 실시한다.
- 구체적인 점검 기준은 `docs/UI_SCALING.md`를 따른다.

## ADR-020 — 정오표 뱃지는 실제 자료가 확인된 경우에만 표시한다
- `availability=available`인 정오표만 목록과 교재 상세 페이지에 표시한다.
- 정오표가 없다고 확인된 경우는 `unavailable`, 아직 확인하지 못한 경우는 `unknown`으로 저장하고 둘 다 UI에서는 숨긴다.
- 주기적 collector가 새 정오표를 확인하면 `available`로 바꾸고 그때부터 뱃지가 자동으로 나타난다.
- 숨겨진 정오표의 `needs_review` 상태는 교재 전체 상태 배지에 영향을 주지 않는다.
## ADR-021 — MP3·부가자료도 존재 확인 후에만 뱃지를 표시한다
- 정오표와 동일하게 `availability=available`인 MP3/부가자료만 사용자 화면에 표시한다.
- 수능특강 영어 계열처럼 MP3가 수백 개 존재하는 경우 특정 파일 하나를 임의의 대표 direct_url로 선택하지 않는다.
- 대신 교재별 EBS MP3 상세 페이지를 `resource_page`로 연결하여 사용자가 단원·문항별 파일을 선택할 수 있게 한다.
- 파일 목록이 비어 있거나 교재 일치 여부가 불확실하면 `unknown`으로 숨긴다.
- EBSi MP3/부가자료는 주기적으로 재점검하고 상태가 바뀔 때만 자동 PR을 생성한다.
## ADR-022 — 초등·중등 자동 점검은 전체 미확인 교재를 순환한다
- 정답·정오표 점검은 매번 정렬된 목록의 앞부분만 반복하지 않고, 실행 회차마다 다음 묶음으로 이동한다.
- 주 2회 실행 기준으로 초등/중등 각각 제한된 수량만 검사해 GitHub Actions 비용과 EBS 요청량을 줄인다.
- 교재가 많아져도 미확인 교재 전체가 순차적으로 점검되도록 rotating batch를 사용한다.
- 수동 전체 점검이 필요하면 `limit-per-site=0`을 사용한다.
- 정오표는 정확한 교재별 게시물 자체가 확인되면 뱃지를 표시하고, 첨부가 하나로 검증된 경우에만 direct_url을 사용한다.
## ADR-023 — EBS 초등·중등 표지는 공식 cbox URL만 자동 반영한다
- 표지는 재호스팅하지 않고 EBS 공식 `cbox.ebs.co.kr/textbook/` 이미지만 catalog에 저장한다.
- 해당 교재의 `textbookId`가 이미지 URL에 포함되어야 한다.
- 실제 `image/*` HTTP 응답과 최소 파일 크기를 확인한다.
- 후보가 여러 개인 경우 자동으로 하나를 선택하지 않는다.
- 표지가 없는 교재만 순환 점검하고, 확인된 표지가 생기면 자동 PR로 반영한다.
## ADR-024 — 무거운 브라우저 probe는 catalog-only PR마다 재실행하지 않는다
- `Validate catalog`는 모든 PR에서 항상 실행한다.
- EBS Playwright probe는 collector/workflow 코드가 변경될 때 smoke test로 실행한다.
- 교재 자료 변화 감시는 정답/정오표/MP3/표지별 scheduled sync workflow가 담당한다.
- 단순 `data/catalog.json` 수정만으로 여러 Playwright workflow를 동시에 재실행하지 않는다.
- 목적: 교재 수가 수백 권으로 늘어도 PR 하나마다 브라우저 설치·외부 사이트 요청이 폭증하지 않도록 한다.
- 실제 자료 자동 반영은 여전히 검증된 공식 링크만 대상으로 하고, 변경이 있을 때만 별도 PR을 만든다.
