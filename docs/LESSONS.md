## 2026-10-06 — 초기 구조

### 직접 다운로드 URL만 모으면 유지보수가 취약함
- 증상: 출판사가 파일 경로나 다운로드 방식을 바꾸면 링크가 즉시 무효화될 수 있음.
- 해결: book_id/resource_id를 URL과 분리하고 official_page/resource_page/direct_url을 계층적으로 저장.
- 교훈: 새 수집기에서도 직접 URL만 반환하지 말고 상위 공식 페이지를 함께 수집.

### HTTP 200만으로 정상 답지라고 판정하면 안 됨
- 증상: 200 응답이어도 로그인 페이지나 메인 페이지일 수 있음.
- 해결: 공통 링크체커는 네트워크/redirect 변화 감지에 집중하고 실제 교재 검증은 출판사별 수집기에서 보강.
- 교훈: 200 = 답지 정상으로 단정하지 않는다.

### redirect는 오류가 아니라 변경 신호임
- 증상: 기존 주소가 301/302 뒤 정상 페이지로 이동할 수 있음.
- 해결: final_url과 redirect chain을 저장.
- 교훈: 새 공식 주소 후보로 활용하되 자동 교체하지 않는다.

### Markdown 문서 내용을 자동 생성 코드에 넣을 때 문자열 충돌
- 증상: 문서의 코드 표기용 기호가 JavaScript 템플릿 문자열과 충돌해 파일 생성 스크립트가 SyntaxError로 중단됨.
- 결과: GitHub에는 잘못된 파일이 쓰이지 않았음.
- 해결: 멀티라인 문서를 안전한 line-array join 방식으로 작성.
- 교훈: 대량 파일 생성 자동화에서는 문서 내용의 구분기호와 실행 스크립트 문자열 문법을 분리한다.

## 2026-10-06 — EBS 1차 구조 조사

### 정답지와 정오표는 서로 다른 엔드포인트
- 초기 입력에서 정답지 URL과 정오표 URL이 동일하게 전달됨.
- 실제 정오표 메뉴는 bkErrChrgMngList.ebs로 확인.
- 교훈: 사용자가 제공한 URL도 메뉴 링크와 실제 페이지 제목을 함께 검증한다.

### EBS는 교재별 고유 bookId를 안정적인 결합키 후보로 사용 가능
- 2027 수능완성 영어의 교재 ID는 LB00000005984.
- 교재 상세 URL의 bookId를 publisher_book_id로 보존한다.
- 교훈: 제목 문자열보다 출판사 내부 고유 ID를 우선해서 자료와 강좌를 결합한다.

### 교재 하나에 자료 타입과 강좌가 여러 개 붙을 수 있음
- 영어 교재는 MP3, 정답지, 정오표가 동시에 노출됨.
- 관련강좌도 복수 강사가 존재할 수 있으므로 단일 URL 필드가 아니라 배열로 설계한다.

## 2026-10-06 — PR #2 UI / 티스토리 embed 프로토타입

### 2열 큰 카드형은 교재 수가 많아질수록 탐색성이 떨어짐
- 증상: 교재가 3~20권일 때는 보기 좋지만 수백 권 이상이면 한 화면에 보이는 정보량이 부족하고 스크롤이 길어짐.
- 해결: 기본값을 1열 compact 목록형으로 바꾸고, 표지 중심 탐색은 별도 표지형 보기로 분리.
- 추가: 최초 20권만 렌더링하고 사용자가 더보기로 확장하도록 설계.
- 교훈: 예쁜 카드 수보다 대량 데이터 탐색 속도를 우선한다.

### 티스토리 iframe과 전체 검색 사이트는 같은 화면을 그대로 쓰면 불필요한 선택지가 많음
- 증상: EBS 영어 글 안에서도 출판사와 과목을 다시 선택하게 하면 포스팅 문맥과 맞지 않고 사용자가 한 단계를 더 거침.
- 해결: `publisher`, `subject`, `grade`, `book`, `embed` URL 파라미터를 도입하고 이미 고정된 선택창은 숨김.
- 교훈: 데이터와 렌더러는 하나로 유지하되, 포스팅의 scope만 URL로 제한한다.

### 외부 표지 이미지는 항상 표시된다고 가정하면 안 됨
- 증상: 출판사 CDN 경로 변경, hotlink 제한, 파일 삭제로 표지가 깨질 수 있음.
- 해결: `cover_image_url`을 선택 필드로 두고 이미지 로딩 실패 시 placeholder를 표시. 링크체커에도 표지 URL을 포함.
- 교훈: 표지는 보조 정보이며 교재 식별과 자료 접근 기능을 막아서는 안 된다.

### 100발100중 샘플을 로그인 필요로 분류한 것은 잘못된 초기 가정이었음
- 증상: 공개 학습자료실에서 정답 및 해설 목록을 로그인 없이 확인할 수 있음.
- 해결: 샘플 교재의 `access`를 `public`으로 수정하고, 실제 개별 direct URL은 별도 검증 전까지 `needs_review` 유지.
- 교훈: 출판사 사이트의 로그인 존재 여부와 특정 자료의 공개 접근 여부를 분리해서 확인한다.



## 2026-10-06 — EBS collector 착수 전 probe 단계 분리

### 검색엔진에서 보이는 URL만 보고 바로 수집기를 고정하면 오래된 파라미터를 섞을 수 있음
- 증상: 정답지 상세의 `bookId` 규칙은 반복 확인되지만, MP3처럼 과거 게시물에 긴 쿼리 문자열이 남아 있는 페이지는 현재 방식과 같다고 보장할 수 없음.
- 해결: 본 collector 전에 읽기 전용 `ebs_probe.py`를 두어 실제 EBS 응답의 form/input/select/bookId 흔적을 GitHub Actions에서 수집.
- 교훈: 공개 URL의 존재와 최신 요청 규칙의 확정을 분리한다.

### 실행 환경에 따라 EBS 응답을 직접 확인하기 어려울 수 있음
- 증상: 개발 대화 환경에서는 외부 네트워크 제약 때문에 저장소 코드를 직접 실행해 EBS 응답을 검증하기 어려운 경우가 있음.
- 해결: 네트워크가 가능한 GitHub Actions에서 수동 probe를 실행하고 JSON artifact를 보존.
- 교훈: 추측으로 파서를 완성하지 말고, 재현 가능한 서버 측 probe 결과를 다음 구현의 입력으로 사용한다.
