## 2026-10-06 — 초기 구조

### 직접 다운로드 URL만 모으면 유지보수가 취약함
- 증상: 출판사가 파일 경로나 다운로드 방식을 바꾸면 링크가 즉시 무효화될 수 있음.
- 해결: book_id/resource_id를 URL과 분리하고 official_page/resource_page/direct_url을 계층적으로 저장.
- 교훈: 새 수집기에서도 직접 URL만 반환하지 말고 상위 공식 페이지를 함께 수집.

### HTTP 200만으로 정상 답지라고 판정하면 안 됨
- 증상: 200 응답이어도 로그인 페이지나 메인 페이지일 수 있음.
- 해결: 공통 링크체커는 네트워크/redirect 변화 감지에 집중하고 실제 교재 검증은 출판사별 수집기에서 보강.
- 교훈: 200 = 답지 정상으로 단정하지 않는다.

### redirect는 오류가 아니라 변경 신호임
- 증상: 기존 주소가 301/302 뒤 정상 페이지로 이동할 수 있음.
- 해결: final_url과 redirect chain을 저장.
- 교훈: 새 공식 주소 후보로 활용하되 자동 교체하지 않는다.

### Markdown 문서 내용을 자동 생성 코드에 넣을 때 문자열 충돌
- 증상: 문서의 코드 표기용 기호가 JavaScript 템플릿 문자열과 충돌해 파일 생성 스크립트가 SyntaxError로 중단됨.
- 결과: GitHub에는 잘못된 파일이 쓰이지 않았음.
- 해결: 멀티라인 문서를 안전한 line-array join 방식으로 작성.
- 교훈: 대량 파일 생성 자동화에서는 문서 내용의 구분기호와 실행 스크립트 문자열 문법을 분리한다.

- 초기 입력에서 정답지 URL과 정오표 URL이 동일하게 전달됨.
- 실제 정오표 메뉴는 bkErrChrgMngList.ebs로 확인.

### EBS는 교재별 고유 bookId를 안정적인 결합키 후보로 사용 가능
- 2027 수능완성 영어의 교재 ID는 LB00000005984.
- 교재 상세 URL의 bookId를 publisher_book_id로 보존한다.
- 교훈: 제목 문자열보다 출판사 내부 고유 ID를 우선해서 자료와 강좌를 결합한다.

- 관련강좌도 복수 강사가 존재할 수 있으므로 단일 URL 필드가 아니라 배열로 설계한다.

### 티스토리 iframe과 전체 검색 사이트는 같은 화면을 그대로 쓰면 불필요한 선택지가 많음
- 증상: EBS 영어 글 안에서도 출판사와 과목을 다시 선택하게 하면 포스팅 문맥과 맞지 않고 사용자가 한 단계를 더 거침.

- 교훈: 데이터와 렌더러는 하나로 유지하되, 포스팅의 scope만 URL로 제한한다.

### 외부 표지 이미지는 항상 표시된다고 가정하면 안 됨
- 증상: 출판사 CDN 경로 변경, hotlink 제한, 파일 삭제로 표지가 깨질 수 있음.
- 해결: `cover_image_url`을 선택 필드로 두고 이미지 로딩 실패 시 placeholder를 표시. 링크체커에도 표지 URL을 포함.
- 교훈: 표지는 보조 정보이며 교재 식별과 자료 접근 기능을 막아서는 안 된다.

### 100발100중 샘플을 로그인 필요로 분류한 것은 잘못된 초기 가정이었음
- 증상: 공개 학습자료실에서 정답 및 해설 목록을 로그인 없이 확인할 수 있음.
- 해결: 샘플 교재의 `access`를 `public`으로 수정하고, 실제 개별 direct URL은 별도 검증 전까지 `needs_review` 유지.
- 교훈: 출판사 사이트의 로그인 존재 여부와 특정 자료의 공개 접근 여부를 분리해서 확인한다.

- 해결: 네트워크가 가능한 GitHub Actions에서 수동 probe를 실행하고 JSON artifact를 보존.
- 교훈: 추측으로 파서를 완성하지 말고, 재현 가능한 서버 측 probe 결과를 다음 구현의 입력으로 사용한다.

## 2026-10-06 — EBS seed 확장 / 사용자 중심 탐색 원칙

### 출판사 사이트의 분류 구조를 그대로 복사하면 전체 사이트가 일관되지 않음
- 증상: EBS는 시리즈·영역·학년·교재 검색이 섞여 있고, 다른 출판사는 또 다른 분류 체계를 사용함.
- 해결: 출판사별 구조는 collector에서 흡수하고 공통 catalog로 정규화. 사용자 UI는 출판사 → 과목 → 학년 → 교재 + 검색으로 유지.
- 교훈: 수집 구조와 사용자 탐색 구조를 분리해야 출판사가 늘어나도 UI가 흔들리지 않는다.

### 티스토리 개별 교재 포스팅을 나중 기능으로 미루면 데이터 계약이 다시 바뀔 수 있음
- 증상: 전체 검색만 기준으로 설계하면 나중에 특정 교재 한 권만 iframe으로 표시할 때 별도 페이지/예외 코드가 필요해질 수 있음.
- 해결: 모든 교재에 안정적인 book_id를 부여하고 처음부터 `?book={book_id}&embed=1`을 기본 계약으로 유지.
- 교훈: 티스토리 개별 포스팅은 부가 기능이 아니라 처음부터 핵심 배포 경로다.

### EBS 시리즈 상세 페이지가 안정적인 bookId 발견 경로가 됨
- 확인: 2027 수능특강 시리즈의 교재 상세 링크에서 LB로 시작하는 EBS 내부 bookId를 연속적으로 확인 가능.
- 적용: 자동 collector 완성 전에는 공식 상세 페이지에서 검증된 bookId를 seed로 추가하고, 자료 direct URL은 검증 후 채운다.
- 교훈: 먼저 교재 식별자를 안정화하고, 다운로드 링크 자동화는 그 다음 단계로 분리한다.
## 2026-10-07 — 목록 링크와 EBS 자료 fallback 분리

### 목록에서 자료 URL을 바로 열면 티스토리/전체 검색의 정보 구조가 약해짐
- 증상: 사용자가 정답 뱃지를 누르자마자 출판사로 이동하면 같은 교재의 정오표·MP3·소개를 한 화면에서 묶어 보여주기 어렵다.
- 해결: 목록의 교재명·표지·자료 뱃지는 모두 내부 `?book={book_id}` 상세 페이지로 모으고, 외부 공식 링크는 상세 화면에서만 연다.
- 교훈: 목록은 '교재 찾기', 상세는 '자료 사용하기' 역할로 분리한다.

### EBS 정답지 상세 주소 자체는 PDF가 아닐 수 있음
- 확인: `detailBkAnsInfo.ebs?...bookId=LB00000005911&no=5...`는 정답지 상세 페이지이며 EBS 다운로드 스크립트는 `bookFlId`를 이용해 별도 다운로드 API를 호출한다.
- 해결: 직접 PDF URL이 검증되면 `direct_url`, 그렇지 않으면 상세 주소를 `resource_page`로 보존한다.
- 교훈: PDF 직링크 자동화가 늦어져도 교재별 상세 주소 fallback 덕분에 사용자 링크가 끊기지 않게 한다.

### 정오표는 사용자가 검색해야 해도 collector는 검색 과정을 대신할 수 있음
- 확인: EBS 정오표 페이지에는 교재명 검색 UI와 `bookNm`, `bookId`, `ctgryCd`, `currentPage` 계열 필드가 존재한다.
- 계획: collector가 동일한 공개 요청을 재현하고 `bookId` 기준 상세 결과를 확인해 정오표 존재 여부와 공식 상세 링크를 저장한다.
- 교훈: 출판사 UI에서 여러 번 클릭해야 하는 과정도 공개 요청 규칙이 확인되면 사용자에게는 한 번의 버튼으로 단순화할 수 있다.

## 2026-10-07 — EBS 브라우저 collector가 정적 probe 한계를 해결

### 정적 HTML에서는 bookFlId가 비어 있어도 렌더링 후 DOM에는 값이 들어옴
- 증상: 단순 HTTP 요청에서는 정답지 상세 HTML의 `bookFlId`를 찾지 못해 PDF direct URL 수집이 막힘.
- 해결: Playwright로 EBS 상세 페이지를 실제 브라우저처럼 렌더링한 뒤 첨부파일의 `fncDownFile('bookFlId')`를 추출.
- 결과: 현재 catalog의 EBS 8권 모두 `bookFlId → bkAnsMngFLdown.ajax → flNm` 경로로 공식 PDF를 확인.
- 교훈: EBS처럼 첨부파일 행이 후속 AJAX로 채워지는 사이트는 브라우저 collector를 출판사 adapter에 포함한다.

### direct URL만 남기지 않고 상세 페이지와 file ID도 함께 보존
- 해결: `direct_url`에는 PDF, `resource_page`에는 EBS 정답지 상세, `publisher_file_id`에는 bookFlId를 저장.
- 교훈: CDN 경로가 변경되어도 bookId + 상세페이지 + publisher_file_id를 이용해 재수집할 수 있어 유지보수성이 높다.

## 2026-10-07 — EBS 정오표 직접 다운로드와 검색어 자동입력 확인

### 정오표 검색 페이지는 bookNm 쿼리로 교재명을 미리 넣을 수 있음
- 확인: 현재 catalog의 EBS 8권 모두 `bookNm={교재명}`으로 접근했을 때 검색 입력칸에 교재명이 자동 입력됨.
- 적용: 정오표 파일이 없는 교재는 공통 페이지보다 교재명이 입력된 검색 페이지를 우선 fallback으로 사용.
- 교훈: 직접 파일이 없더라도 사용자의 검색 단계를 한 단계 줄일 수 있다.

### EBS 정오표 다운로드는 bookId만으로 안정적인 공식 엔드포인트를 사용할 수 있음
- 확인: 현재 EBS 8권 중 6권에서 `bkErrChrgMngFLdown.ebs?bookId={BOOK_ID}`가 실제 첨부파일을 반환.
- 파일 확인 교재: 수능특강 독서, 문학, 언어와 매체, 확률과통계, 영어, 영어독해연습.
- 아직 파일 없음: 수능완성 영어, 수능특강 영어듣기.
- 적용: 정오표가 발견된 교재는 direct_url로 바로 연결하고, 나머지는 교재명 prefill 검색 페이지를 유지.
- 교훈: 정오표처럼 드물게 생기는 자료는 주기적 탐색 + 변경 시 PR 방식이 수동 관리보다 적합하다.

## 2026-10-07 — EBS 초등·중학 사이트 분리 대응

### EBS라는 같은 출판사라도 학교급에 따라 사이트와 교재 ID가 다름
- 확인: 고등은 EBSi의 `LB...`, 초등·중학은 각각 EBS 초등/중학 사이트의 `TB...` 교재 ID를 사용한다.
- 해결: 사용자 화면의 출판사는 모두 `EBS`로 통합하고 내부 데이터에 `publisher_site = ebsi | ebs_primary | ebs_middle`을 추가.
- 교훈: 출판사 단위 adapter 안에서도 서비스/학교급별 하위 adapter가 필요할 수 있다.

### 첫 초등·중학 목록 probe는 링크 텍스트를 교재명으로 오인함
- 증상: `textbookId`는 600개 이상 발견했지만 연결된 anchor 텍스트가 대부분 '교재 미리보기' 또는 '정답지/자료'라 실제 교재명을 얻지 못함.
- 원인: 교재명과 TB ID 링크가 서로 다른 DOM 요소에 있음.
